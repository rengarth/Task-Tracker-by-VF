## Ручная проверка в Chromium

Все изменения тестовых задач выполнялись на порту 8081 в `personal_planner_test`.

1. Создание задачи с интервалом 14:00–16:00; сохранение и обновление страницы.
2. Дочерняя задача до 18:00: предварительное подтверждение расширения родителя, после подтверждения новый диапазон сохранён.
3. Пересекающаяся независимая задача: предупреждение с конфликтом; устаревшая ревизия отклоняется после внешнего изменения базы.
4. Запуск таймера, обновление страницы и пауза: состояние сохраняется.
5. Перетаскивание задачи с пятницы на субботу: новая дата сохранена.
6. Изменение нижнего края с 16:00 до 15:30: начало осталось 14:00; обновление страницы сохраняет 14:00–15:30.
7. Undo последнего перемещения возвращает прежний интервал.

Исправлена обработка ввода date/datetime-local, обнаруженная при браузерной проверке: выбранные даты теперь поступают в состояние React через native input.

## Ограничения проверки и реализации

- Браузерные проверки проведены вручную через автоматизацию браузера; отдельного воспроизводимого набора Playwright E2E в репозитории нет. Не все комбинации фильтров, горячих клавиш и масштабов прошли ручной прогон.
- Мобильные жесты, скринридеры, большие объёмы данных и длительное непрерывное использование не тестировались.
- Состояние читается целиком; операции сериализуются глобальной ревизией. Это архитектура для личного локального планировщика, без многопользовательской авторизации и пагинации API.
- Повторы конечные (до 366 экземпляров). При неоднозначном локальном времени DST форма не позволяет выбрать первое/второе вхождение часа.

## Запуск с рабочего стола

Созданы ярлыки «Открыть ежедневник» и «Остановить ежедневник» в профиле Windows. Проверены скрытый запуск JAR через VBS и Windows PowerShell 5, ответ API после запуска, повторное открытие с тем же PID без второго серверного процесса и остановка через отдельный ярлык. После проверки сервер остановлен. При запуске миграции Flyway проверены, пользовательские данные не менялись.

Автоостановка проверена отдельным процессом на `personal_planner_test` и порту 8081 с укороченным интервалом: фоновый GET `/stats` не удержал сервер; POST `/activity` продлил время работы; после следующего полного интервала процесс штатно завершился. Пользовательская база не изменялась. Для обычного запуска интервал составляет 5 часов, проверка выполняется раз в минуту.

Автозагрузка Windows: копия ярлыка «Открыть ежедневник» помещена в пользовательскую папку Startup. Прямое открытие именно этой копии проверено без перезагрузки: браузер открылся, HTTP `/api/v1/state` ответил. Проверка реального входа после включения компьютера остаётся за следующим входом в Windows. Запускатель ждёт готовности PostgreSQL до 60 секунд.

По просьбе пользователя запись автозагрузки переименована в «Трекер»: создан локальный `Трекер.exe` с таким названием файла и описанием, ярлык Startup перенаправлен на него, прежний ярлык через `wscript` удалён. Проверены запуск через новую запись (HTTP 200, без второго Java-процесса) и видимое имя `Трекер` в `Win32_StartupCommand`. Отображение в интерфейсе Диспетчера задач после следующего входа в Windows отдельно не проверялось.
